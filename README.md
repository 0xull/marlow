# Marlow

Marlow is a type-2 virtual machine monitor written from scratch in modern C++, built directly on the Linux KVM API. It boots an unmodified Linux kernel to an interactive shell, serves that guest's I/O through hand-written device models, runs the guest across multiple virtual processors, and snapshots and restores a running guest to disk.

The project is built from the `/dev/kvm` ioctl surface upward with no VMM library underneath it. Guest physical memory is a host mapping that Marlow registers with KVM and manages by hand. The virtual CPU runs on real silicon through the `KVM_RUN` loop, and Marlow services only the exits the hardware cannot handle alone, dispatching port I/O, memory-mapped I/O, and halts to the code that emulates the platform. Every file descriptor and every memory mapping is owned through RAII, so resource lifetimes are structural rather than manual.

The device model is written directly against the hardware interfaces the guest expects. A 16550A UART gives the kernel a serial console. The virtio devices are built on a hand-written implementation of the split virtqueue, meaning the descriptor table, the available ring, the used ring, and the notification doorbell, exposed over the virtio MMIO transport. Marlow ships a virtio-blk device backed by a host file and a virtio-net device wired to a host tap interface, so the guest mounts a real root filesystem and reaches the network. Multiple virtual processors each run on their own host thread, with the shared device model synchronized and verified clean under ThreadSanitizer.

The reason Marlow exists is fast, snapshotted, isolated guest execution, which is the primitive the microVM sandbox industry is built on. Marlow captures the complete machine state of a running guest, meaning the virtual CPU registers, the model-specific registers, the CPUID, the interrupt-controller state, every device's state, and the full guest memory, and it restores that state into a fresh process so the guest resumes exactly where it paused. The restore path handles the timekeeping hazards that a naive restore gets wrong, so the resumed guest keeps correct time and working timers rather than merely staying alive. On top of full restore, Marlow implements differential snapshots driven by the KVM dirty-page bitmap and copy-on-write forking of a running guest, and it reports measured restore and fork latencies rather than asserted ones.

Marlow targets x86-64 Linux hosts with KVM enabled. It is a from-scratch implementation built to be understood at the level of individual ioctls and emulated registers, so the code favors clarity and defensibility over feature breadth, and every performance claim in the project is one that has been measured with the method shown.
